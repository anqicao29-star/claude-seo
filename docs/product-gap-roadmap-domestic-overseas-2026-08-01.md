## 一、产品结构结论

不开发两套独立产品，而是保留一个公共核心，再增加国内和海外两个交付模式。

```text
Codex SEO 公共核心
├── 企业知识库
├── 网站与品牌诊断
├── 问题和关键词研究
├── 内容策划、生成与审核
├── 任务和证据管理
└── 效果监测与报告

国内模式
├── 信源规划
├── 多平台内容适配
├── 媒体目录和报价
├── 发布任务与供应商协作
└── 收录、提及和引用验证

海外模式
├── 官网/CMS 发布
├── 技术 SEO 实施
├── 索引提交
└── 搜索流量与 AI 引用监测
```

## 二、P0：国内商业闭环必须补充

P0 是完成第一批国内付费客户前必须具备的功能。第一阶段允许人工交付，不要求全部自动化。

### 1. 企业知识库

- [ ] 企业全称、简称、品牌名和曾用名
- [ ] 官网、电话、地址、邮箱和服务地区
- [ ] 产品、服务、价格区间和目标客户
- [ ] 企业资质、荣誉、专利和可验证证书
- [ ] 客户案例、数据、图片和证明文件
- [ ] 创始人、专家和作者信息
- [ ] 竞品与差异化卖点
- [ ] 禁止出现的表述和行业合规规则
- [ ] 每条事实的证据来源、更新时间和可信状态
- [ ] 信息冲突检查，防止不同文章出现不同电话、地址或产品数据

### 2. 国内信源诊断

- [ ] 输入品牌和目标问题，保存各 AI 平台原始回答
- [ ] 提取回答中的品牌、竞品、引用域名和引用页面
- [ ] 对信源分类：官网、新闻、垂直媒体、自媒体、问答、视频、B2B、地图、百科、政府或协会
- [ ] 判断客户已有信源覆盖和缺口
- [ ] 区分“免费可运营渠道”和“需要付费投放渠道”
- [ ] 输出建议优先级、理由、风险和预估成本区间
- [ ] 不把单次 AI 回答中的排序包装成稳定排名

### 3. 多渠道内容包

- [ ] 官网深度文章
- [ ] 新闻稿版本
- [ ] 行业媒体投稿版本
- [ ] 知乎问答版本
- [ ] 百家号、搜狐号、头条号等自媒体版本
- [ ] B2B 产品介绍版本
- [ ] 抖音、小红书、视频号口播和图文版本
- [ ] 企业简介、品牌事实页和 FAQ
- [ ] 标题、摘要、图片、Alt、作者、来源和发布时间建议
- [ ] 相似度、事实一致性、广告法和行业合规检查
- [ ] 每个平台单独改写，不允许同一文章无差别铺发

### 4. 发布任务中心

- [ ] 客户、项目、关键词和文章关联
- [ ] 目标平台或媒体
- [ ] 发布方式：客户自发、我方代发、第三方供应商
- [ ] 媒体成本、对客报价和预计毛利
- [ ] 提交、审核、驳回、发布、删除和退款状态
- [ ] 发布 URL、发布日期和页面截图
- [ ] 供应商订单号和备注
- [ ] CSV/XLSX 导入导出
- [ ] 支持批量导入供应商返回的发布结果
- [ ] 所有外部发布动作在提交前人工确认

### 5. 发布后验证

- [ ] URL 是否可以访问
- [ ] 页面标题、正文和品牌信息是否与提交版本一致
- [ ] 是否存在 noindex、异常 canonical 或登录限制
- [ ] 百度、必应及其他可检测渠道的收录状态
- [ ] AI 是否提及品牌
- [ ] AI 是否引用发布 URL 或对应域名
- [ ] 是否出现错误、负面或过期信息
- [ ] 保存每次检查时间、原始回答、引用 URL 和截图
- [ ] 区分发布量、收录量、提及量、引用量、访问量、询盘量和成交量

### 6. 客户报告

- [ ] 发布清单和实际 URL
- [ ] 媒体类型分布
- [ ] 收录率、品牌提及率和引用率
- [ ] 优化前后对比
- [ ] 竞品对比
- [ ] 失败项、不可验证项和下一步行动
- [ ] 清楚标注数据采样时间、平台、提示词和检测方法
- [ ] 输出 Markdown、PDF 和 XLSX

## 三、P1：国内模块规模化后补充

### 1. 媒体目录

- [ ] 媒体名称、域名、行业、地区和渠道类型
- [ ] 供应商及采购价
- [ ] 对客销售价和毛利
- [ ] 审核要求、禁投行业和内容限制
- [ ] 平均发布时间、历史成功率和删稿率
- [ ] 历史收录率、品牌提及率和 AI 引用率
- [ ] 不使用无法验证的“媒体权重”或“AI内部评分”

### 2. 供应商接口

- [ ] 采用供应商无关的统一发布任务模型
- [ ] 媒体查询和报价同步
- [ ] 下单前人工确认
- [ ] 查询订单状态
- [ ] 回收发布 URL
- [ ] 退款和失败原因同步
- [ ] API 密钥只保存在用户本机安全存储中
- [ ] 首期最多接入一到两家稳定供应商

### 3. 信源效果数据库

- [ ] 记录行业、地区、问题、媒体类型和实际结果
- [ ] 统计不同渠道的收录率、提及率和引用率
- [ ] 形成“什么客户适合什么信源”的推荐依据
- [ ] 将供应商宣传指标和实际验证指标分开
- [ ] 数据不足时明确显示样本量，不输出伪精确结论

## 四、P0/P1：海外方向需要补齐

现有系统已经覆盖大部分海外网站诊断、内容和技术 SEO 能力，以下功能用于把“生成文章”补成“发布和验证闭环”。

### P0：基础交付

- [ ] 将文章写入本地 Markdown、MDX 或代码仓库指定目录
- [ ] 支持 WordPress 草稿发布
- [ ] 发布前显示 Diff 并要求用户确认
- [ ] 自动推荐标题、Meta Description、Slug、Canonical 和 Schema
- [ ] 自动推荐内部链接和锚文本
- [ ] 生成 Sitemap 更新建议
- [ ] 发布后检查页面状态和基础索引条件
- [ ] 支持 Google Search Console、Bing Webmaster 和 IndexNow 工作流

### P1：更多 CMS 与监测

- [ ] Webflow
- [ ] Shopify
- [ ] Ghost
- [ ] Wix
- [ ] GitHub/GitLab 提交或 PR 工作流
- [ ] AI 引用和品牌提及历史监测
- [ ] Search Console 的展示、点击、页面和查询监测
- [ ] 内容衰退和更新提醒
- [ ] 线索或转化事件回填

## 六、商业产品层级

### 免费钩子

- 基础网站 SEO/GEO 诊断
- 少量品牌和提示词检测
- 信源缺口摘要
- 一篇内容 Brief 或示例文章
- 不包含付费媒体成本

### 国内付费工具/社群

- 企业知识库
- 完整信源规划
- 多渠道内容包
- 发布任务管理
- 监测和客户报告
- 模板、培训和社群答疑

### 国内增值服务

- 媒体采购和发布
- 代运营
- 行业合规审核
- 月度监测和复盘
- 顾问咨询

### 海外付费产品

- 全站审计
- 内容集群和文章生产
- CMS 或代码仓库发布
- 技术 SEO 修复
- 索引和 AI 可见度监测
- 月度咨询或代运营

## 七、暂时不要做

- [ ] 不自建大规模媒体采购网络
- [ ] 不同时接入大量供应商
- [ ] 不自动登录几十个自媒体账号批量发布
- [ ] 不承诺 7 天霸榜、全平台前三或固定推荐位置
- [ ] 不把发布条数等同于 GEO 效果
- [ ] 不生产虚假案例、伪造专家、虚构数据或不真实品牌提及
- [ ] 不把国内媒体采购成本纳入无限量订阅
- [ ] 不急于开发 OEM、贴牌、代理商充值体系
- [ ] 不为了国内模块破坏本地单机和可审计的产品定位

## 八、建议开发顺序

### 第一阶段：可人工交付的最小闭环

1. 企业知识库。
2. 国内信源诊断。
3. 多渠道内容包。
4. 发布任务中心。
5. 发布 URL 批量导入。
6. 收录、提及和引用验证。
7. 客户报告。

### 第二阶段：海外发布闭环

1. 本地 Markdown/MDX 写入。
2. WordPress 草稿发布。
3. 内链、Schema 和索引工作流。
4. Search Console/Bing 数据回收。

### 第三阶段：国内供应商 API

1. 用前 10 至 20 个真实客户验证媒体需求。
2. 统计供应商成功率、删稿率和实际效果。
3. 选择一至两家供应商接入。
4. 建立媒体效果数据库。

## 九、第一版验收标准

国内第一版不要求自动下单。满足以下条件即可开始收费验证：

- 可以为一个企业建立可信知识库；
- 可以根据品牌和问题输出信源缺口；
- 可以生成至少三种渠道版本的内容；
- 可以导出清晰的发布任务表；
- 可以导入发布 URL；
- 可以保存 AI 原始回答和引用证据；
- 可以生成一份客户看得懂、数据可复核的前后对比报告。

达到这个标准后，产品已经不是单纯的 SEO 审计工具，也不只是批量发文工具，而是一套本地运行、可由人工和供应商协同完成交付的 SEO/GEO 工作台。
