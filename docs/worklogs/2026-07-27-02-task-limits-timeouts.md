## 大白话总结

以前虽然可以取消任务，但仍有两个问题：

1. 网页可以同时启动很多任务，可能一下子占满电脑的 CPU、内存和网络。
2. 如果 Codex 或某个脚本卡住，任务可能一直运行，没有自动停止时间。

这次增加了两道保险：

- 默认同一时间只允许运行 1 个任务。用户重复发送第二个任务时，后台不会再启动一个 Codex，而是明确告诉用户“当前任务过多，请稍后重试”。
- 每个任务默认最多运行 15 分钟。超过时间后，后台会真正终止对应 Runtime，并把结果标记为超时。

简单说：现在既不会因为连续点击而同时启动一堆任务，也不会让一个卡死的任务整晚运行。

## 本次完成内容

1. 集中配置增加最大并发任务数：
   - 环境变量：`CLAUDE_SEO_MAX_CONCURRENT_TASKS`
   - 默认值：`1`
   - 允许范围：`1–4`
2. 集中配置增加任务超时时间：
   - 环境变量：`CLAUDE_SEO_TASK_TIMEOUT_SECONDS`
   - 默认值：`900` 秒
   - 允许范围：`30–3600` 秒
3. 非法配置会回退到安全默认值。
4. 超出允许范围的配置会自动收敛到边界值。
5. 任务状态机增加：
   - `timeout_requested`
   - `timed_out`
6. 达到并发上限时返回：
   - HTTP `429`
   - 错误码 `task.capacity_exceeded`
   - `retryable: true`
7. 超时后：
   - 调用 Runtime `terminate()`。
   - 任务最终状态变为 `timed_out`。
   - v1 流返回 `task.failed`。
   - 错误码为 `task.timeout`。
8. 用户主动取消优先保持为“已取消”，不会被稍后触发的计时器错误覆盖成超时。
9. Runtime 状态接口会返回当前并发和超时配置。

## 当前限制

- 超时计时从 Runtime 会话建立后开始，不覆盖程序启动前的系统级卡死。
- 前端暂时不显示剩余时间或倒计时。
- 并发限制目前按整个本地服务计算，不区分不同工作区。
- 任务和计时器都保存在内存中，应用重启后不会恢复。
- 还没有结构化日志记录任务开始、结束、取消和超时。
