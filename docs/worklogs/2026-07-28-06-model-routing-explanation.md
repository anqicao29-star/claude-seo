# 工作日志：确认文章到底由谁生成

- 日期：2026-07-28

- 工作类型：只读检查与产品说明
- 状态：已确认，没有修改程序功能

## 大白话总结

当前工作台不是让 Codex 指挥 Claude 写文章，而是在发送任务前直接选择一个模型：

- 选择“SEO/文件任务 · Codex”时，请求直接交给 Codex。
- 选择“文章创作 · Claude”时，请求直接交给本机 Claude Code CLI，正文由 Claude 模型生成。

两个模型不会同时参与同一条普通请求，Codex 也不会先改写文章要求再转交给 Claude。

用户刚才收到“这里是我在写，不是 Claude 在写”的回答，是因为当时使用的是“SEO/文件任务 · Codex”模式。这个回答与当前路由规则一致，但它没有把网页上的模式选择解释清楚，所以容易让人误以为文章始终由 Codex 生成。

## 本次检查内容

1. 检查网页任务类型选项。
2. 检查前端发送给后台的 `task_type`。
3. 检查后台模型路由表。
4. 检查 Claude CLI 适配器的实际启动命令。
5. 检查文章任务路由自动化测试。

## 检查结论

- `general` 路由到 `CodexCliRuntime`。
- `article` 路由到 `ClaudeCliRuntime`。
- 文章模式会直接启动本机 `claude` 命令。
- 文章模式的提示词明确要求 Claude 完成正文，不得转交给 Codex。
- 项目已有自动化测试，验证文章任务确实路由到 Claude。

## 用户现在应该怎么用

如果要写完整文章：

1. 在聊天区顶部选择“文章创作 · Claude”。
2. 确认页面右上角显示“Claude 已登录”。
3. 把主题、关键词、目标受众、篇幅和全部写作要求一次性发送。

如果选择“SEO/文件任务 · Codex”，即使输入内容看起来像文章需求，当前版本仍会由 Codex 执行，不会自动转给 Claude。
