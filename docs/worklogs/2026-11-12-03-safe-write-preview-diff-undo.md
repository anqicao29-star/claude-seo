## 大白话总结

以前网页一旦允许 Codex 修改文件，它会直接碰项目原文件，用户来不及检查。这次把这条链路改成了“先在隔离副本里改”。Codex 完成后，网页先展示改了哪些文件和具体 Diff；只有用户点击“确认应用修改”，内容才会写进真实项目。写入后如果发现不对，还可以点击撤销恢复。

这次也用真实 Codex 完整测试了一遍：让它新增一个测试文件，预览时原项目里没有该文件；确认后文件出现且内容正确；撤销后文件消失。说明不是只做了界面按钮，后台的隔离、确认和恢复链路确实能工作。

## 本次做了什么

1. 新增隔离写入区，Codex 的修改先落到缓存副本，不直接进入真实项目。
2. 在聊天结果中展示新增、修改、删除的文件清单和统一 Diff。
3. 新增“确认应用修改”“放弃修改”“撤销本次修改”三个操作。
4. 应用前再次核对原文件哈希；如果用户或其他程序已经改过文件，就拒绝覆盖。
5. 应用修改前自动保存备份，并用原子替换降低写到一半中断的风险。
6. 阻止 `.env`、密钥、证书、Git 内部目录、虚拟环境等敏感路径进入自动写入流程。
7. 限制二进制文件、非 UTF-8 文件、超大文件、超多文件和超大 Diff。
8. 任务失败、取消、超时或浏览器断开时，丢弃尚未完成的隔离修改。
9. 预览状态保存到磁盘，服务重启后仍能继续确认、放弃或撤销。
10. 修正 Codex 默认模型兼容问题，把本机 Codex CLI 从 `0.142.4` 更新到 `0.167.2`，工作台默认使用当前可用的 `gpt-6.1-sol`；旧版 CLI 会在网页提示运行 `codex update`。
11. 更新产品待办，将 `BETA-03` 标记为进行中。
12. 重新生成本地分发包。
