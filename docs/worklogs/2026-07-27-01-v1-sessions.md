## 大白话总结

以前网页为了“继续上一轮对话”，会直接保存 Codex 自己的内部线程编号。这个编号属于 Codex Runtime，不应该成为网页协议的一部分。Codex 一旦升级、换版本或更换模型，这种直接依赖就容易失效。

这次给产品增加了自己的会话编号：

- 网页只认识 `session_...`。
- 后端在内存里保存“产品会话编号”和“Codex 内部线程编号”的对应关系。
- 网页继续对话时，只把产品会话编号交给后端。
- 后端自己找到对应的 Codex 线程并续接。
- Codex 内部线程编号不再进入网页、本地存储或 v1 接口响应。

同时，聊天消息已经切换到正式的 v1 事件格式。每条事件都有协议版本、任务编号、事件编号、顺序和时间。前端不再依赖 Codex CLI 原始输出。

简单说：以前网页拿着 Codex 的“内部工号”直接办事；现在网页只拿产品自己的“客户号”，内部工号由后台保管。

## 安全与隐私变化

- Codex 内部线程 ID 不再暴露给 v1 客户端。
- 浏览器本地存储只保存应用会话 ID。
- 客户端不能伪造或直接要求恢复某个 Codex 内部线程。
- Runtime 版本变化可以在后端适配，不需要改变网页协议。
